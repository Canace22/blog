定义

Claude 跨设备继续任务时，需要把三件事分开：

  • Skill 保存做法（说明、脚本、依赖安装和续跑方式）
  • 会话 决定任务在哪里继续（云端会话，或 Remote Control 本地会话）
  • 执行环境 真正运行脚本、安装依赖和处理素材

电脑和手机只是不同入口，不是执行环境本身。

来源

  • 笔记本都合上了，Claude 为什么还能在手机上执行电脑上装的技能？
  • 我让 Claude 给视频里的人脸打码，顺手做成了一个 Skill
  • 原来我一直用错了 Cowork

核心区分

Skill 不带走本机状态

Skill 最简单时只有一份 SKILL.md，复杂时还可附带脚本和参考文件。它记录的是可重复流程，不会把某台电脑已经装好的 ffmpeg、deface、OpenCV 和当前运行状态一起带走。

本机 ~/.claude/skills/ 里的 Skill 也不会自动进入 Cowork 或云端会话。需要在 claude.ai 账号中启用，或作为项目 Skill 提交到代码仓库。

会话类型决定能不能关电脑

类型 任务实际跑在哪 合上电脑后
云端会话 Claude 的云端执行环境 可以继续；Skill 从账号载入
Remote Control 电脑上的本地 Claude Code 会话 不行；机器休眠后连接暂停

“可以换到手机继续”不等于手机接管了电脑里的运行环境。

执行环境负责依赖和计算

换设备后，新环境要自己拿到 Skill、素材和依赖。云端沙盒里单条命令常有约 45 秒时限，因此长时间任务需要断点续跑。本机直接跑命令通常没有这种固定时限。

Cowork 的沙箱限制（不能直接在用户电脑上执行命令）与这里的云端执行环境是同一类问题：产品把计算放在受控环境里，换来安全和跨设备，也带来超时、依赖重装和文件上传边界。

实践含义

  • 电脑适合把流程调通、检查脚本和处理细节；手机适合补交素材、查看进度或接收结果。
  • 跨设备好用的前提是 Skill 写可靠：脚本、依赖、安装命令、步骤和续跑方式都要写下来。
  • 涉及人脸视频等隐私素材时，应先确认文件上传位置、保存时长和访问范围。
  • 要确认某次任务跑在云端还是本地，应回看会话类型和环境记录，不能只凭 Skill 里的超时设计下结论。

与本 Wiki 的关系

  • 提升 AI Coding 稳定性的经验上下文模式：Skill 是经验单元；本文补上它不携带执行环境。
  • Claude Code 常见工作流：官方会话恢复、计划任务之外，还需区分云端会话与 Remote Control。
  • AI 辅助开发：Skill 沉淀之后，还要按任务选择设备和会话类型。
